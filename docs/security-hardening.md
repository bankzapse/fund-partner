# การเสริมความปลอดภัย — สรุปสิ่งที่ทำแล้วและสิ่งที่ควรทำต่อ

เอกสารนี้สรุปการอุดช่องโหว่จากการตรวจแบบปฏิปักษ์ (adversarial audit) รอบล่าสุด
เพื่อให้ทีมและผู้ตรวจภายนอกเห็นภาพว่าปิดอะไรไปแล้ว และอะไรควรทำเพิ่ม

## ทำแล้ว (อยู่ในโค้ด + มีเทสต์ครอบ)

### การเข้าถึงและข้อมูลรั่ว
- ไฟล์แนบ (สำเนาบัตร ปชช./สลิป) ต้องล็อกอินก่อนเสมอ และบน production ใช้
  **Supabase bucket แบบ private + signed URL อายุสั้น** — ดู `storage-private-bucket.md`
- `preview` การชำระตรวจสิทธิ์ตามเขตพนักงานเหมือนตอนบันทึกจริง (กัน IDOR)
- ปิดเส้นทาง admin GET (`/employees` `/settings` `/approvals`) ที่ยังขาดการ์ดสิทธิ์
- error 500 ไม่ส่งข้อความดิบของฐานข้อมูลกลับ (กันเปิดเผยโครงสร้างภายใน)

### ความถูกต้องของยอดเงิน
- แยก transaction ด้วย `AsyncLocalStorage` — กัน query ข้าม transaction เมื่อมีหลายคำขอพร้อมกัน
- ยกเลิกรายการที่ระบบสร้างเองคู่กับสัญญา (เงินปล่อยใหม่/ค่าทำเอกสาร/จ่ายฟรี/ดอกรียอด)
  เดี่ยว ๆ จากสมุดเงินสดไม่ได้ (กันยอดเงินสด-กำไรเพี้ยน)
- นำเข้าสัญญาที่ชำระครบต้องปิดทุกงวด ไม่เหลืองวดค้างบนสัญญาที่ปิดแล้ว

### ส่วนหัว/เบราว์เซอร์
- เพิ่ม `Content-Security-Policy`, `Cross-Origin-Opener-Policy`, `Permissions-Policy`
  (ตั้งทั้งใน `vercel.json` และฝั่ง Express) — ย้าย inline script เป็นไฟล์เพื่อใช้ `script-src 'self'`
- กัน CSV formula injection (นำหน้าค่าที่ขึ้นต้นด้วย `= + - @` ด้วย `'`)

### บัญชีผู้ใช้และการยิงถล่ม
- **ยืนยันตัวตนสองชั้น (2FA) แบบ TOTP** — ใช้แอป Authenticator ทั่วไป (node:crypto ล้วน, RFC 6238)
  มีรหัสสำรอง 10 ชุด (ใช้แล้วทิ้ง), เจ้าของรีเซ็ตให้พนักงานที่ทำมือถือหายได้,
  ปิด 2FA ต้องยืนยันรหัสผ่าน, secret/รหัสสำรองไม่หลุดออก API หรือไฟล์สำรอง
- นโยบายรหัสผ่าน: อย่างน้อย **8 ตัวอักษร**, กันรหัสยอดฮิตและตัวอักษรซ้ำตัวเดียว
- หา IP ผู้เรียกให้ปลอมยาก: ใช้ `X-Real-IP` ก่อน แล้วค่อยค่าขวาสุดของ `X-Forwarded-For`
  (ไม่ใช้ค่าซ้ายสุดที่ผู้เรียกกรอกเองได้) — กันการหมุน IP เพื่อเลี่ยง rate limit/login lock
- เพดานกันยิงถล่ม API แบบหยาบระดับ instance (`src/lib/rate-limit.js`) เสริมจาก login lock เดิม

## ควรทำต่อ (นอกโค้ด หรือรอบถัดไป)

| เรื่อง | หมายเหตุ |
|---|---|
| สลับ Supabase bucket เป็น private + ย้ายข้อมูลเก่า | ต้องทำในหน้า Supabase — ดู `storage-private-bucket.md` |
| Rate limit ระดับ edge (Vercel WAF) | เพดานในโค้ดเป็น backstop ระดับ instance เท่านั้น ควรตั้งที่ Vercel อีกชั้น |
| บันทึกการเข้าถึงข้อมูลส่วนบุคคล (PDPA access log) | รอแนวทางจากทนาย |
| หน้านโยบายความเป็นส่วนตัว | รอเนื้อหาจากทนาย |
| สำรองข้อมูลอัตโนมัติ + นโยบายเก็บข้อมูล (retention) | งานรอบถัดไป |
| นำเข้า Excel: reconcile กรณี paid_installments ไม่ตรงยอดยกมา | ปิดเคสชำระครบแล้ว เหลือเคสชำระบางส่วนที่ข้อมูลต้นทางไม่ตรง |

## ตัวแปรแวดล้อมที่เกี่ยวข้อง
- `FP_RATE_LIMIT` — จำนวนคำขอต่อ IP ต่อนาที (ค่าเริ่มต้น 600) ปรับได้ตามการใช้งานจริง
- `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_STORAGE_BUCKET` — สำหรับไฟล์แนบบน production
